> 基于 Python / tkinter 的期权 Delta 动态对冲回测框架，支持多种奇异期权、多数据源接入、日内多频率调仓与蒙特卡洛分析。

---

## ✨ 功能特性

- **5 大类期权**：香草 (Vanilla)、累计 (Decumulator)、亚式 (Asian)、气囊 (Airbag)、雪球 (Snowball)，共 14 种子类型
- **3 种数据源**：蒙特卡洛模拟 / CSV 历史行情 / Wind API
- **3 种对冲触发方式**：每日收盘 / 每日固定时刻 / 固定价格间隔（绝对价格、相对价格或日波动 σ 三种执行口径，可在参考点互相换算）
- **统一仓位方向**：左侧买入 / 卖出是 GUI 全部回测的唯一方向来源；单次、多路径、历史 C2C 与全部候选在任务启动时冻结同一方向，数量只能使用正数
- **可选收盘兜底**：左侧对冲策略区提供唯一公共开关，普通回测与历史择优共享每日收盘 Delta 对齐规则；原策略已在同一根收盘 bar 触发时自动去重
- **智能行情粒度**：Wind 支持“自动（推荐）”采样粒度，按策略选用日频或兼容的日内 bar；CSV / Wind 真实行情仍按时间索引与交易 session 自动推导每日 bar 数
- **回测结果池对比**：逐次回测后按需保留结果，买卖方向分组，以同方向最早保留的 close-to-close 快照为基准，再勾选其它快照即时比较
- **独立历史择优**：近周、近月、近季、近半年、近年五档周期可复选（默认全选、至少一项），使用 CSV / Wind 真实历史严格连续回放所选周期，并提供固定 C2C 加多个候选的完整 `L` 日累计 PnL 主视图
- **独立路径采样**：独立 `mc_seed` 多路径采样，避免样本相关性过高
- **完整可视化**：6 宫格对冲图表、波动率分析、蒙特卡洛盈亏分布、结构扫描；每日明细只展示并导出对冲触发记录
- **真实行情缩放**：CSV / Wind 模式下，以首日价为锚点等比例自动缩放期权参数（行权价、障碍价、赔付金额等），保持结构的相对一致性

## 🚀 快速开始

### 环境要求

- **Python 3.10+**（使用了 `match/case` 语法）
- 推荐 3.11 或更高版本

### 安装依赖

```bash
pip install -r requirements.txt
```

> Wind 数据源为可选依赖，需安装 Wind 终端 + Python 插件（`WindPy`）。模拟和 CSV 模式无需 Wind。

### 启动 GUI

```bash
python gui_app.py
```

窗口默认大小 1600×1000，最小 1200×720。启动后会自动加载 [assets/deltalab.ico](assets/deltalab.ico)（Windows）或 [assets/deltalab.png](assets/deltalab.png)（macOS / Linux）作为窗口图标。

### 运行回测

1. **期权类型** → 选 `香草期权 (Vanilla)`
2. **期权参数** → 保留默认（ATM Call, 22 天, σ=0.18）
3. **回测设置** → 数据来源选 `模拟`，模拟路径数改为 `500`
4. 点击 **▶ 运行回测**
5. 点击 **＋ 保留当前结果到对比**，修改对冲策略或参数后再次运行并保留
6. 打开 **⚖ 回测结果对比**，勾选快照即时查看累计净 PnL、排名和差异
7. 查看 `回测摘要` / `对冲图表` / `波动率分析` / `盈亏分布` 等标签页

### 📦 下载预编译版本

Windows / macOS (Apple Silicon) 用户可直接从 [Releases](https://github.com/Grefer/DeltaLab/releases) 下载免安装包（无需 Python 环境）：

- `DeltaLab-vX.Y.Z-windows-x86_64.zip` — 解压后双击 `DeltaLab.exe`
- `DeltaLab-vX.Y.Z-macos-arm64.zip` — Apple Silicon (M 系列)

> macOS 首次打开若提示"未知开发者"，请在 `访达 → 应用程序` 中 **右键 → 打开**，或在 `系统设置 → 隐私与安全性` 中允许。
>
> Intel Mac 用户请从源码运行（见上方"启动 GUI"），仅需 `pip install -r requirements.txt && python gui_app.py`。

## 📊 支持的期权类型

可以通过点击 **📊 绘制结构图** 查看期权结构说明与 Greeks 扫描曲线。

| 大类 | 子类型数 | 定价方式 |

| 香草期权 (Vanilla) | 1（欧式） | Black-Scholes 封闭解 |

## 对冲模式与策略比较

回测引擎支持每日收盘 `CloseToCloseStrategy`、每天多个固定时刻
`FixedTimeStrategy(["23:00", "11:30", "15:00"])`，以及统一带宽策略。
GUI 单次回测和历史择优的默认固定时刻均为 `23:00,11:30,15:00`；
该顺序按同一交易日的“前一自然日夜盘 → 次日日盘”排列；
无夜盘品种会按交易时段自动跳过 `23:00`。
`HedgeBandStrategy` 可选择绝对价格、相对百分比或动态 σ 三种阈值；
例如 `HedgeBandStrategy("absolute", threshold=50)`、
`HedgeBandStrategy("relative", threshold=0.01)` 或
`HedgeBandStrategy("sigma", k=0.5)`。旧的 `PriceIntervalStrategy` 与
`SigmaBandStrategy` 仍作为兼容入口保留。
在同一个参考价格和年化波动率下，三种单位可以互相换算：
`relative = absolute / S_ref`，
`sigma_multiple = absolute / (S_ref × sigma_annual / √ANNUAL_DAYS)`，因此也有
`sigma_multiple = relative / (sigma_annual / √ANNUAL_DAYS)`；当前项目统一使用
`ANNUAL_DAYS=243`。这只是参考点上的阈值对应关系，并不表示三种执行口径在整条
动态路径上严格等价：绝对口径保持固定价差，相对口径随上次实际对冲价计算，σ
口径还会按所选 implied / realized 来源和历史波动率回看期动态计算。
GUI 会同时显示绝对间隔、相对间隔和日波动 σ 倍数；编辑任意一项后按回车或
移出输入框，即会根据当前期权的 `s0` 与年化 `sigma` 自动反推另外两项；
修改参考参数也会自动刷新。普通单次回测始终按用户最后编辑的原始单位执行。
CSV/Wind 将期权从参考价伸缩到真实首价时，绝对带宽会按同一比例伸缩；相对值
和 σ 倍数保持不变。固定时刻模式要求真实日内 `DatetimeIndex`。Wind 行情会先按
当前代码对应的交易时段筛选目标：明确落在休市区间的时刻（例如无夜盘品种配置了
`23:00`）自动跳过，并在结果中同时披露请求、实际生效和跳过的时刻；仍处于有效
交易时段的目标则必须在每个纳入回测的交易日组中都有对应 bar，缺失时继续明确
报错。CSV 没有可靠的品种交易时段元数据，因此保持严格模式，不会凭“历史中没
出现过”猜测为休市。

GUI 在左侧对冲策略区提供唯一的公共「每日收盘兜底对冲」开关，普通回测与历史择优
共用该控制；历史择优启动时会冻结其当前值并应用到全部候选。开启后，无论选择每日收盘、
固定时刻还是固定间隔，回测都会在每个**非到期、非敲出**交易日组的最后一根 bar
保证一次 Delta 对齐；若原策略已在该 bar 触发（例如每日收盘策略、包含实际收盘
时刻的固定时刻策略，或恰好在收盘越界的固定间隔策略），只合并为一次触发，不会
重复调仓或重复计费。到期或敲出所在的末 bar 不先做兜底对冲，而是直接把标的头寸
平至 `0`。这里的“收盘”按交易日组的最后一根真实 bar 判定，并非硬编码 `15:00`；
无时间戳路径则按引擎采用的 `steps_per_day` 划分日末。

左侧「头寸方向」同样是所有 GUI 回测的唯一方向来源：`1` 表示卖出期权，
`-1` 表示买入期权。单次、多路径和历史择优都会在任务启动时冻结该值；历史
C2C 与全部候选共享同一方向。`quantity` 必须是有限正数，不能再用负数量隐式
翻转买卖方向。结果内部保留模型原始 Greeks，同时提供并用于展示
`-position × quantity × raw Greek` 的组合仓位 Greeks。

GUI 只提供上述三种业务策略，默认使用每日收盘；多策略比较也只比较这三类
（行情不具备真实日内时刻时会跳过固定时刻）。旧的 `FixedFreqStrategy` 与
`hedge_freq` 参数仅作为后端 API 兼容入口保留，不再出现在 GUI 或默认策略比较中。
模拟来源可单独设置「模拟采样 bar/日」，用于控制路径离散化；CSV / Wind 不允许
手填每日 bar 数，底层会按真实时间索引和交易 session 自动推导。

Wind 单次回测以「建仓日」为日期主控；默认根据期权剩余期限自动补足请求结束日，
也可关闭自动结束后手工指定。原来的「频率」改为「行情采样粒度」，推荐保留
「自动（推荐）」：每日收盘策略使用日频，固定时刻策略使用能覆盖目标时刻的分钟
行情，固定间隔策略采用推荐的日内检查粒度；界面会披露最终实际采用的粒度。
因此默认配置不再出现“日频行情却运行固定时刻策略”的隐含冲突。这里选择的是
行情请求与触发检查粒度，并不恢复可手填的「每日 bar 数」。

`pricing.hedge_analysis` 提供 `compare_strategies` 批量分析策略，并提供
`summarize_strategy_result` 将已经完成的单次回测转换为统一指标；同时用
`recommend_by_rolling_history` 在单一标的的严格尾部历史区间上输出所选周期的
择优结果与完整排名；可选目录为近周、近月、近季、近半年、近年，期货品种入口另由
`recommend_by_contract_history_pool` 按历史具体合约边界完成同样的比较。每个周期
都从共同分析截止日向前连续回放最近 `L` 个交易日，而不是在最近 `L` 日里挑选若干
终点、再向前扩出完整期权期限。所有 bar 损益会先按真实交易日聚合；单一标的按**增量收益 / 增量性价比**排名
（各段日净 PnL 接续后与 C2C 逐日相减），跨具体合约的品种池因金额尺度不可相加，
改按逐段相对 C2C 的 RMS 改善加权汇总。

期权剩余期限 `T` 只定义历史代理合约每一段的最长存续期，不再扩大证据区间。
当 `L <= T` 时，整段严格区间作为一个代理段，区间末按剩余期限公允价值 MTM；
当 `L > T` 时，系统在区间内按 `T` 续接代理段，完整段到期结算，最后不足 `T`
的尾段 MTM。GUI 的五档周期默认全选且至少保留一项；不再维护或传递
`5 / 12 / 24 / 36 / 48` 的终点预算。

GUI 的“回测结果对比”是独立的会话内结果池：每次普通回测成功后，用户可显式
命名并保留轻量结果快照；修改策略或参数继续回测不会覆盖旧快照。进入该页面后，
点击结果池“显示”列即可即时更新累计净 PnL、四张摘要卡、评分排名和相对基准
差异。评分排名仍按日净 PnL RMS 选出最优结果，但所有相对指标固定参照会话内
同方向最早保留的 `close_to_close` 快照，选择其它结果时会自动带入该基准，避免
基准随勾选项漂移；买入与卖出结果不会进入同一排名。缺少同方向每日收盘快照时
只展示绝对排名并明确提示。整个过程只读取已完成
结果，不重新运行回测。快照可重命名、删除；行情路径、
同一方向内的期权参数或成本口径不一致时仍允许并列查看，但界面会提示排名仅供
场景对照。该页面只管理普通回测快照，不承载历史搜索参数或历史排名。结果池仅保存
在当前应用会话，关闭程序后清空。

“◷ 历史择优”是与单次回测、回测结果对比平级的独立页面。每日收盘 C2C 固定为
不可关闭的历史比较基准；五档分析周期可复选，默认全部勾选且运行前至少保留一项；
候选策略开关、固定时刻
列表与固定间隔候选均在该页面配置，不再混入单次回测参数区；候选带宽的 σ 恒取
左侧输入的波动率，界面不再提供来源选项。它复用统一的指标与回测引擎，在 CSV / Wind 真实历史上只运行
已选周期的严格连续回放。历史页不重复提供收盘兜底开关，而是在任务启动时读取并
冻结左侧公共开关与头寸方向；全部历史候选及 C2C 共享这些规则。每个候选只使用
与 C2C 成功配对的共同代理段和共同评分日（成本已计入）。单一标的序列按**增量**
排名，两个可切换口径：`增量收益 = Σ(候选日净 PnL − C2C 日净 PnL)`（默认）与
`增量性价比 = mean(逐日增量) / std(逐日增量)`；两者在回测时一并算出，点表头即可
切换而不必重跑。品种历史合约池跨合约价格与金额尺度不同，无法相加金额，改为在每个
非重叠代理段内计算有界 C2C RMS 改善再按该段实际评分日数加权——该模式下增量三列
显示 `—`、表头不可点，周期说明会写明实际排名依据。界面同时披露代理段数、到期
段数、MTM 段数和实际评分日。
历史页的 Wind 日期与采样粒度同样独立于单次回测：用户主要指定历史分析截至日，
系统按 `max(L_selected) + V` 个评分/预热交易日取得行情，并额外请求一个
Day 0 收盘锚点，其中
`L_selected` 是已选周期的交易日范围；默认全选时最大值为近年的 `243` 日。
代理期限 `T` 不再参与历史请求范围；`V` 是 realized-HV 预热，未使用 realized
σ 时 `V=0`。
也可在高级设置中手工覆盖请求范围与粒度。同一次历史搜索的全部候选共享同一个
Wind 请求粒度；具体历史合约仍按各自真实时间索引推导每日 Bar 数，避免历史交易
时段变化把完整代理段误判为残缺。

Wind 期货代码按输入语义严格路由：`P2609.DCE` 视为明确的单个合约，只分析该合约
自身的历史，绝不自动汇集同品种；`P.DCE` 视为品种入口，系统用分析截止日之前的
Wind `trade_hiscode` 逐日主力映射，只从最长已选周期的证据范围自动加载真实出现过的
具体历史合约（包含截止日主力）。区间外只允许为 Day 0 锚点和 realized σ 的
`V` 日预热读取必要行情，不会因 `T` 再向前扩展。代理段会披露实际合约代码；
不会引入截止日后才成为主力的合约。具体期货合约使用不复权行情，股票 / ETF
的单序列历史仍使用前复权口径。
固定间隔候选统一用日波动 σ 倍数表达，默认
为 `0.5, 0.75, 1, 1.5, 2`，用户可编辑逗号列表；留空表示不额外加入常用档位。
启用“加入当前回测带宽”时，当前绝对 / 相对 / σ 输入会按当前 `s0` 与年化
`sigma` 换算成 σ 候选后加入。所有候选按 10 位有效数字规范去重，包含当前输入
在内最多 10 档。

历史择优中的固定间隔案例统一按 `sigma` 策略执行，σ 恒取左侧输入的波动率
（`implied`），使不同价格水平的历史代理段共享同一波动尺度，也保证排名比的是带宽
倍数本身而不是混进另一条策略维度。回测引擎仍支持 `realized`，只是不再从择优页
进入——因此该页也不需要 HV 预热区间。这不会改变普通单次回测按原始输入单位执行
的行为。模拟来源会在入口直接禁用或拒绝，不启动任务，也
不会生成“历史推荐”。真实历史读取或严格区间推荐计算失败时，整项任务失败，不会
退化为仅展示当前路径后仍提示完成。

候选覆盖严格区间内全部 C2C 基准代理段才具备正式历史择优资格；历史不足但现有
代理段完全配对时只作诊断，候选自身缺段时不能成为领先者。若候选均不如基准，
历史最优参考会明确显示“维持每日收盘”；主排名改善与 C2C 持平时也固定优先基准，避免
为没有历史改善的候选增加复杂度。历史排名与普通回测快照口径不同，因此不会直接
混排。历史页在排名表下方用一条动作栏收拢三个衔接动作：“加载分段到展示页”
“仅回填参数”和“当前路径验证”。

“加载分段到展示页”是把优选结论真正带进其它展示界面的主入口：选中排名行后，
旁边的“历史分段”下拉会列出该候选在当前周期内跑过的每个回测分段（含分段序号、
真实起止日、具体合约与终止口径），点击后按该分段原始的行情切片、缩放后的期权与
策略对象重跑同一段历史，并把逐 bar 结果直接渲染到回测摘要、对冲图表、每日明细和
波动率分析。因此可以在每日明细里逐条查看该候选在这段历史中的建仓、策略触发、
收盘保底与终止记录，而不是只看排名分数。加载完成的结果同时成为“当前回测”，可以
直接用“保留当前结果到对比”送进结果池。历史择优只保留逐日摘要，bar 级结果数组在
渲染后即释放；这里改为记录重放配方（行情切片 + 期权 + 策略 + 回测参数），既能完整
复现原分段结果，又不会让分钟级历史长期占用内存。失败或未与每日收盘配对的候选没有
可重放分段，下拉为空并明确提示。

另外两个动作面向“换到当前环境重跑”：“仅回填参数”只把策略参数写回单次回测区，
不运行任何回测。“当前路径验证”是唯一的验证入口，实际范围由周期排名表首列的
勾选决定，动作栏下方的说明会随勾选实时写明这一点：没有勾选时只按当前单次回测
环境执行选中的那一条推荐策略，并把完成后的普通快照送入结果池；有勾选时按
排名表首列已勾选的候选顺序逐条执行同样的当前路径验证：方向固定为点击时的左侧
选择，每条成功后自动以“优选『周期』·『策略』”命名保留快照；结果池中缺少同方向
每日收盘快照时会先补跑一条基准，使结果对比页的相对指标立刻可用；全部完成后自动
切换到结果对比页并勾选本批快照。单条历史行元数据残缺只跳过该条并在末尾汇总原因，
回测本身失败
或无法启动则中止剩余候选并列出未验证项，已完成的快照仍保留在结果池。区间不足不是
计算失败：此时正式历史参考可以为空，只要仍能返回非空诊断排名且至少有一个有效
代理段，任务就会成功并标记“区间不足，仅诊断”，同时显示代理段配对与历史覆盖；
若一个有效代理段都无法形成，则优先提示缺失的具体合约、主力日或固定时刻等真实
原因，再建议扩大历史区间。品种池中单个旧合约加载失败只会让涉及它的周期降级，
不会阻断其它可用代理段；明确输入具体合约时则不会为了补足长期证据而扩展到同品种。

历史结果只包含本次勾选的周期，不为未选周期生成空白结论或图表。历史图表位于周期
排名表下方，固定以每日收盘 close-to-close 为基准；排名表首列可
勾选最多三个候选，默认显示前两个可比候选。该勾选同时决定图表曲线与“当前路径
验证”的批量范围，`勾选前2名` 可恢复默认，`清空勾选` 则退回单条验证。
所有曲线只使用 C2C 与已勾选候选在同
周期、同代理段且段内长度一致的成功共同交集。默认“完整 L 日累计路径”按严格区间
顺序拼接全部非重叠共同代理段的日 PnL 后再累计，使主图与排名使用的完整证据一致；
若候选失败导致共同交集不足 `L` 日，图表会明确标记实际日数，失败段不补零。
“单代理段路径”和“多代理段中位路径”保留为诊断视图：前者查看某个代理段的累计
净 PnL、成本前 PnL 或成本，后者按代理段内交易日展示中位数，并只为 C2C 与主候选
绘制 P25/P75 描述区间。若共同代理段少于排名表的独立配对段，界面会明确提示两者
分母不同。固定时刻缺 Bar 的代理段不会被填充。结果页同步披露策略/C2C 汇总 RMS、
较 C2C 改善、
代理段胜率、配对覆盖和品种池实际参与合约。单代理段路径与汇总 RMS
仍是金额口径；其中品种池的汇总 RMS 仅作诊断，主排名使用按实际评分日加权的
逐段有界改善。品种池跨多个具体合约的完整路径与多代理段中位路径均按各代理段
`PnL / (S0 × multiplier × |quantity|)` 安全归一化后再拼接或聚合。若乘数或数量
为 0、`S0` 非正，或同代理段候选与 C2C 的分母不一致，相关聚合图会明确停用，不会
退回误导性的跨合约原始金额曲线。这些指标只用于历史参考，不构成置信区间、显著性
结论或未来表现保证。
